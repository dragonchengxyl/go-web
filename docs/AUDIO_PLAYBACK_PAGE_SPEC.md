# 音频专业播放页规格说明

> 时间点：2026-03-20
>
> 目标：为社区音频作品建立一个真正面向“收听”的专业播放页，而不是继续依赖作品详情页 + 底部迷你播放器的组合。

## 1. 当前现状

当前音频播放能力由三部分构成：

- 作品卡片可直接触发全局播放器
- 底部有一个全局迷你播放器
- `/audio/works/[id]` 是作品详情页，包含基础播放、点赞、收藏、评论

现有实现已经能播放，但还不是“专业播放页”：

- 播放器状态仍然是单曲模型，没有队列、上一首、下一首、循环、随机
- 详情页里同时存在原生 `<audio controls>` 和全局播放器，播放入口不统一
- 没有明确的“沉浸式收听”页面结构
- 没有播放来源上下文，例如“从作品列表进入”、“从创作者页进入”
- 没有继续收听、相关推荐、创作者更多作品等听歌场景能力

## 2. 核心决策

### 2.1 路由决策

不新增独立 `/player/[id]`。

直接把现有 `/audio/works/[id]` 升级为专业播放页。

原因：

- 现有链接、分享路径、SEO、站内跳转都已围绕该路径建立
- 避免重复维护“详情页”和“播放页”两套相似页面
- 便于逐步演进，不需要大规模迁移入口

### 2.2 播放器层级

- 底部播放器继续保留，作为全局迷你播放器
- `/audio/works/[id]` 变为“展开态”的主播放页
- 所有播放入口都统一驱动同一套播放器 session

### 2.3 用户目标

新页面主要服务三类需求：

- 进入作品后，稳定、清晰地收听完整内容
- 在听的过程中完成点赞、收藏、评论、切换相关推荐
- 从一个来源连续听下去，而不是每首都重新开始找

## 3. MVP 范围

第一个可上线版本必须包含以下模块：

- 主播放区
  - 大封面 / 默认视觉
  - 标题、作者、时长、标签、发布时间
  - 主播放按钮、暂停按钮
  - 进度条
  - 当前时间 / 总时长
  - 音量控制

- 扩展播放控制
  - 上一首
  - 下一首
  - 循环模式
  - 随机播放开关

- 队列与来源上下文
  - 当前队列列表
  - 当前曲目标识
  - 能显示本次队列来源，例如“来自最新作品”

- 作品信息
  - 描述
  - 标签
  - 创作者基本信息

- 社区互动
  - 点赞
  - 收藏
  - 评论列表
  - 发表评论

- 推荐区域
  - 更多音频作品
  - 优先展示同作者更多作品，其次展示公开作品推荐

## 4. 暂不进入 MVP

以下能力明确不进入第一版播放页：

- 歌词逐行高亮
- 章节标记 / A-B Loop
- 播放速度切换
- 设备间同步播放进度
- 桌面快捷键提示面板
- 波形精细编辑器
- 真实专辑 / 曲目体系改造
- 商业化购买 / 单曲售卖

这些能力保留为二期或三期增强项，不影响首版上线。

## 5. 页面信息架构

### 5.1 Desktop

- 左侧主区
  - 封面
  - 标题 / 作者 / 元信息
  - 核心播放控制
  - 进度区
  - 作品简介
  - 评论区

- 右侧侧栏
  - 当前播放队列
  - 创作者更多作品
  - 推荐作品

### 5.2 Mobile

- 顶部封面与标题
- 中部播放控制和进度区
- 下方折叠区
  - 队列
  - 简介
  - 评论
  - 推荐

移动端优先保证：

- 主操作按钮处于拇指易达区域
- 底部播放器和页面主播放器不互相遮挡
- 切歌和返回时不丢失当前播放状态

## 6. 用户流

### 6.1 从作品卡片进入

1. 用户在列表页点击卡片播放按钮
2. 系统创建播放 session，并注入来源队列
3. 底部迷你播放器立即开始播放
4. 用户可继续停留原页面，或点击标题 / 封面进入 `/audio/works/[id]`

### 6.2 从作品页进入沉浸播放

1. 用户打开 `/audio/works/[id]`
2. 页面直接展示专业播放布局
3. 若当前 session 就是该作品，页面复用现有状态
4. 若当前没有 session，则页面自动创建以该作品为当前项的 session

### 6.3 连续收听

1. 用户点击“下一首”
2. 系统根据 session queue 切换曲目
3. 页面内容随当前曲目同步更新
4. 评论、点赞、收藏上下文切换到新作品

## 7. 播放状态模型要求

现有 `currentTrack` 单曲模型需要升级为 session 模型。

MVP 必须支持以下状态：

- `queue`
- `currentIndex`
- `isPlaying`
- `volume`
- `currentTime`
- `duration`
- `repeatMode`
- `shuffle`
- `sourceContext`
- `openedFrom`

其中：

- `queue` 表示本次连续播放的曲目集合
- `sourceContext` 用于还原本次播放来源，例如首页最新作品、创作者页、搜索结果
- `openedFrom` 用于返回逻辑和后续埋点分析

## 8. 数据要求

MVP 尽量复用现有接口，但需要确认以下数据来源：

- 当前作品详情：已有
- 评论列表：已有
- 点赞 / 收藏状态：已有
- 同作者更多作品：可能需要新增或复用列表接口
- 推荐作品：首版可先复用公开作品列表 + 前端筛选

如果现有接口不足，后续阶段允许新增：

- `GET /audio/works/:id/related`
- `GET /users/:id/audio-works`

## 9. 与现有页面的关系

### 9.1 保留

- `/audio/works` 公开作品列表页
- 底部全局迷你播放器

### 9.2 升级

- `/audio/works/[id]` 从“详情页”升级为“专业播放页”

### 9.3 删除或收口

- 删除播放页中的原生 `<audio controls>`
- 所有播放入口统一走播放器 session
- 页面内不再出现两套互不关联的播放状态

## 10. 验收标准

当第一版完成时，应满足以下标准：

- 用户从作品列表、首页、创作者页进入播放时，都会进入同一套播放状态模型
- 底部播放器和 `/audio/works/[id]` 的播放状态完全同步
- 页面内不存在第二套原生 `<audio>` 控件作为主播放入口
- 用户可以完成上一首、下一首、循环、随机、调整音量
- 评论、点赞、收藏在播放页内可以直接完成
- 移动端和桌面端都能正常使用，不出现播放器遮挡主操作区
- 页面刷新后不会导致明显错误状态，至少当前曲目页面可以恢复并继续播放

## 11. 后续阶段拆分

### 第 2 阶段

设计播放页信息架构和组件结构。

### 第 3 阶段

重构播放器状态，从单曲模型升级到 session 模型。

### 第 4 阶段

统一所有播放入口，接入同一播放器 session。

### 第 5 阶段

完成专业播放页 UI 与交互实现。

### 第 6 阶段

补齐接口、验证、回归测试和上线检查。
