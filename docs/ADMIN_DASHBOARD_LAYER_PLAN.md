# 管理后台仪表盘夹层规划

> 更新时间：2026-03-27
> 面向当前仓库现状，不是假设一个全新后台。

## 1. 目标

当前后台已经有较完整的工作页：

- `/admin` 运营总览
- `/admin/analytics` 数据分析
- `/admin/games` 游戏观测
- `/admin/moderation` 内容审核
- `/admin/reports` 举报处理
- `/admin/audio-works` 音频治理
- `/admin/users` 用户管理
- `/admin/groups` 圈子运营
- `/admin/events` 活动运营
- `/admin/orders` 订单运营
- `/admin/comments` 评论管理
- `/admin/audit-logs` 审计日志
- `/admin/assistant` AI 助手
- `/admin/permissions` 权限矩阵
- `/admin/system` 系统配置

问题不在于“没有后台页”，而在于：

- 入口是线性左侧导航，缺少“按工作目标分层”的仪表盘夹层
- `/admin` 更像单个运营总览，而不是整个后台的 dashboard directory
- 治理、运营、增长、系统、游戏都混在同一层，日常巡检路径不够短
- 不同角色进入后台后，看不到“今天先看哪几个盘”

本次仪表盘夹层的目标是：

1. 让 `/admin` 成为“后台总入口 + 仪表盘分发页”
2. 把现有后台页面归并为 5 到 6 个高价值仪表盘域
3. 优先复用现有页面和接口，再补新的聚合接口

## 2. 推荐信息架构

建议把后台分为两层：

- 第一层：仪表盘夹层
  - 负责按工作目标分发，而不是直接进明细表格
- 第二层：具体工作台
  - 负责列表、筛选、审核、状态变更、导出

推荐保留 `/admin` 作为夹层首页，并把它设计成一个 dashboard directory。

## 3. 建议保留的 6 个仪表盘

### 3.1 指挥总览盘

- 建议路由：`/admin`
- 面向角色：管理员、值班运营、版主
- 作用：每天先看一眼，确认平台是否稳定、今天先处理什么

P0 必备模块：

- 平台核心指标
  - 总用户
  - 今日新增
  - 帖子存量
  - 待处理举报
- 待办队列
  - 待审帖子数
  - 待处理举报数
  - 待审音频数
  - 高风险评论数
- 快速入口
  - 去审核
  - 去举报
  - 去用户管理
  - 去游戏观测
- 异常提醒
  - 最近 24 小时是否出现支付异常、AI 配置缺失、游戏房间异常

现状判断：

- 你现在的 `/admin` 已经是这个盘的雏形
- 还缺少“仪表盘卡片导航”和“异常汇总条”

### 3.2 增长与业务盘

- 建议路由：`/admin/analytics`
- 面向角色：运营负责人、产品、创作者运营
- 作用：看增长趋势和业务走势，不做具体治理动作

P0 必备模块：

- 用户增长趋势
- 内容增长趋势
- 举报趋势
- 订单趋势
- 活动与圈子活跃度趋势

P1 推荐补充：

- 发帖转化
- 新用户 7 天留存
- 创作者活跃度
- 音频播放事件趋势

现状判断：

- 当前 `/admin/analytics` 已有用户增长和基础快照
- 还缺帖子增长、订单趋势、创作者趋势

### 3.3 内容治理盘

- 建议路由：新增 `/admin/governance`
- 面向角色：审核、版主、值班运营
- 作用：把所有“内容风控与治理”聚成一个盘，再分流到具体工作页

P0 必备模块：

- 待审帖子
- 待处理举报
- 待审音频作品
- 需要巡检的评论
- 最近审计动作

落地页映射：

- 帖子审核 -> `/admin/moderation`
- 举报 -> `/admin/reports`
- 音频治理 -> `/admin/audio-works`
- 评论管理 -> `/admin/comments`
- 审计日志 -> `/admin/audit-logs`

现状判断：

- 这些页面已经存在
- 缺的是一个聚合盘，而不是新的治理子系统

### 3.4 社区运营盘

- 建议路由：新增 `/admin/community`
- 面向角色：社区运营、用户运营
- 作用：统一看用户、圈子、活动和社区秩序

P0 必备模块：

- 用户总量、封禁数、待处理账号问题
- 圈子总量、私密圈子数、异常圈子
- 活动总量、报名中活动、已结束未复盘活动
- 高活跃用户 / 高风险用户列表

落地页映射：

- 用户管理 -> `/admin/users`
- 圈子运营 -> `/admin/groups`
- 活动运营 -> `/admin/events`

P1 推荐补充：

- 用户角色分布
- 圈子发帖量排行
- 活动报名转化率

### 3.5 商业与创作者盘

- 建议路由：新增 `/admin/commerce`
- 面向角色：商业运营、创作者运营
- 作用：统一管理订单、赞助、创作者内容生产和公开分发

P0 必备模块：

- 订单总量、待处理订单、失败订单
- 本周打赏金额
- 待发布音频任务 / 待审核音频作品
- 赞助目标完成度

落地页映射：

- 订单运营 -> `/admin/orders`
- 音频治理 -> `/admin/audio-works`
- 系统配置中的赞助配置 -> `/admin/system`

P1 推荐补充：

- 创作者收入排行
- 音频发布成功率
- 播放到互动转化

### 3.6 游戏与实时运行态盘

- 建议路由：`/admin/games`
- 面向角色：研发、运营、值班人员
- 作用：集中看游戏房间、对局结果、战报和异常情况

P0 必备模块：

- Hex Blitz 活跃房间
- 斗地主活跃房间
- 最近对局
- 排行榜快照
- 房间异常提示

P1 推荐补充：

- WS 连接数
- 房间创建失败率
- 平均对局时长
- 断线重连次数

现状判断：

- 当前 `/admin/games` 已经是比较成熟的一块
- 这块可以直接作为夹层中的独立仪表盘保留

### 3.7 AI 与平台配置盘

- 建议路由：新增 `/admin/platform`
- 面向角色：管理员、研发支持
- 作用：统一看 AI 助手、运行时配置、权限矩阵和平台健康

P0 必备模块：

- AI 助手配置状态
- 运行时配置快照
- 权限矩阵摘要
- 关键审计动作趋势
- 基础设施配置状态

落地页映射：

- AI 助手 -> `/admin/assistant`
- 系统配置 -> `/admin/system`
- 权限矩阵 -> `/admin/permissions`
- 审计日志 -> `/admin/audit-logs`

## 4. 仪表盘夹层本身要长什么样

推荐 `/admin` 首页从“单一运营总览”升级为三段式结构：

### 第一屏：值班态摘要

- 今日关键指标
- 告警与待办
- 快速处理按钮

### 第二屏：仪表盘目录

- 6 张 dashboard cards
- 每张卡展示：
  - 名称
  - 一句话说明
  - 当前最值得关注的 2 到 3 个数字
  - 跳转按钮

### 第三屏：跨域异常流

- 最近 24 小时异常
- 最近后台关键操作
- 最近需要关注的业务波动

这样后台首页就不只是“一个盘”，而是“进入其他盘的夹层”。

## 5. 推荐实施顺序

### Phase 1：只做夹层，不大改现有工作页

- 保留现有 `/admin/*` 页面
- 把 `/admin` 改成 dashboard directory + 总览
- 在左侧导航顶部新增“仪表盘”分组
- 新增 3 个聚合页占位：
  - `/admin/governance`
  - `/admin/community`
  - `/admin/commerce`

### Phase 2：补聚合接口

建议新增以下聚合 API：

- `GET /api/v1/admin/dashboards/governance`
- `GET /api/v1/admin/dashboards/community`
- `GET /api/v1/admin/dashboards/commerce`
- `GET /api/v1/admin/dashboards/platform`

原则：

- 聚合接口返回卡片数据和待办摘要
- 明细仍然留在现有列表接口

### Phase 3：补跨域告警与 SLA

- 待审超时提醒
- 举报超时未处理提醒
- 支付异常提醒
- 音频任务失败提醒
- 游戏房间异常提醒

## 6. 当前最值得先做的盘

如果只允许先做一轮，我建议优先顺序如下：

1. 指挥总览盘升级成“夹层首页”
2. 内容治理盘
3. 社区运营盘
4. 商业与创作者盘
5. AI 与平台配置盘
6. 增长与业务盘继续深化

理由：

- 你当前后台最成熟的是治理、运营、游戏和系统配置
- 增长分析可以继续做，但不是后台值班效率的第一优先
- 先把“去哪看”理顺，再补更细的趋势图和聚合指标

## 7. 一句话建议

当前后台不缺页面，缺的是“把页面组织成工作面”的夹层。

下一阶段不应该继续平铺更多列表页，而应该先把后台升级成：

- 一个总入口盘
- 五到六个领域仪表盘
- 每个仪表盘再进入现有工作台
