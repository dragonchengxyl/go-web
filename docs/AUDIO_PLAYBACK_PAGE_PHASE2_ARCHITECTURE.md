# 音频专业播放页架构设计

> 对应阶段：Phase 2
>
> 前置文档：`docs/AUDIO_PLAYBACK_PAGE_SPEC.md`

## 1. 目标

本阶段输出可直接指导编码的页面结构设计，包括：

- 页面信息架构
- 桌面与移动布局
- 组件树与职责边界
- 数据来源与依赖关系
- 页面状态归属
- 从现有 `/audio/works/[id]` 平滑迁移的收口点

本阶段不修改播放器状态模型，不改全局播放逻辑。

## 2. 页面定位

目标页面仍然是：

- `/audio/works/[id]`

但语义从“作品详情页”升级为：

- “专业播放页”

它承担两类角色：

- 作为单首作品的沉浸式收听入口
- 作为全局播放器的展开态视图

## 4. 信息架构

页面拆为 6 个一级区块：

1. 页面头部导航区
2. 主播放 Hero 区
3. 队列与发现侧栏
4. 作品元信息区
5. 评论创作区
6. 评论列表区

### 4.1 页面头部导航区

目标：

- 保留返回作品列表能力
- 显示当前来源上下文
- 为未来“返回来源页”保留位置

内容：

- 返回按钮
- 来源标签，例如“来自最新作品”
- 当前页类型标签，例如“播放页”

### 4.2 主播放 Hero 区

目标：

- 用户进入页面后 1 屏内就能开始收听
- 让播放成为视觉中心，而不是把互动排在前面

内容：

- 大封面
- 标题
- 作者
- 基础徽标信息
- 核心播放控制
- 进度区
- 音量区
- 波形可视化

### 4.3 队列与发现侧栏

目标：

- 支撑连续收听
- 给下一阶段 session 模型预留 UI 容器

内容：

- 当前队列
- 当前曲目标识
- 同作者更多作品
- 推荐作品

### 4.4 作品元信息区

目标：

- 让描述、标签、发布时间等信息在播放器下方自然展开
- 不打断播放主路径

内容：

- 描述
- 标签
- 发布时间
- 作品来源信息

### 4.5 评论创作区

目标：

- 用户在听的同时能直接表达反馈

内容：

- 评论输入框
- 发表评论按钮
- 登录提示

### 4.6 评论列表区

目标：

- 让播放页具备社区作品页的互动深度

内容：

- 评论计数
- 评论列表
- 加载态 / 空态

## 6. 组件职责

### `AudioPlaybackHeader`

负责：

- 返回导航
- 来源上下文标签
- 顶部页头样式

不负责：

- 任何播放器控制

### `AudioPlaybackHero`

负责：

- 组合封面、元信息、主控制区、进度区
- 作为 1 屏核心视觉容器

不负责：

- 拉取数据
- 队列逻辑

### `AudioPlaybackArtwork`

负责：

- 渲染封面图
- 无封面时提供默认视觉

### `AudioPlaybackMeta`

负责：

- 标题
- 作者
- 发布时间
- 时长
- 统计徽标

### `AudioPlaybackPrimaryControls`

负责：

- 上一首
- 播放 / 暂停
- 下一首
- 循环
- 随机

### `AudioPlaybackProgress`

负责：

- 进度条
- 当前时间 / 总时长
- 拖动 seek
- 音量控制

### `AudioPlaybackWaveform`

负责：

- 波形可视化
- 点击波形跳转的 UI 容器占位

MVP 首版只需要展示与 seek 联动，不需要做复杂波形编辑。

### `AudioPlaybackActions`

负责：

- 点赞
- 收藏
- 举报
- 登录态提示

### `AudioPlaybackQueue`

负责：

- 展示当前 session 的队列
- 高亮当前曲目
- 点击切歌

### `AudioPlaybackCreatorPanel`

负责：

- 创作者身份卡
- 更多作品入口

### `AudioPlaybackRecommendations`

负责：

- 展示更多可继续听的作品

### `AudioPlaybackDetails`

负责：

- 承载描述、标签、发布时间、来源信息

### `AudioPlaybackCommentComposer`

负责：

- 评论输入
- 登录态判断

### `AudioPlaybackCommentList`

负责：

- 评论展示
- 空态 / 加载态

## 8. 状态归属

### 8.1 页面级远程数据

由路由页负责获取：

- 当前作品详情
- 评论列表
- 当前用户对作品的交互状态

### 8.2 播放状态

仍由全局播放器 store 持有，但在 Phase 3 升级模型。

当前阶段只定义未来边界：

- 页面组件不直接持有“当前播放真实状态”
- 页面从全局 store 读取播放信息
- 页面所有控制行为都通过 store action 触发

### 8.3 局部 UI 状态

由局部组件持有：

- 举报弹窗展开状态
- 评论输入草稿
- 本地折叠区域状态

## 9. 迁移策略

从当前页面迁移到专业播放页时，遵守以下规则：

### 9.1 保留的部分

- 评论数据获取逻辑
- 点赞 / 收藏 / 举报 mutation
- 作品查询与 meState 查询
- 波形预览数据

### 9.2 需要移除的部分

- 页面内原生 `<audio controls>`
- 当前“播放与互动”卡片里的混合布局

### 9.3 需要重组的部分

- 顶部 hero 区改为播放主视觉
- 评论输入与评论列表拆为独立区块
- 作品 facts 与 waveform 从卡片中抽离成页面结构一部分

## 10. 视觉方向

播放页建议保持现有站点视觉语言，但更偏“沉浸式音频”：

- 保留深色、玻璃质感、渐变高光
- 强化封面区和进度区的视觉权重
- 减少详情页式分散卡片，改为更连续的大区块
- 队列区和推荐区要清晰，但不喧宾夺主

## 11. Phase 3 交接要求

下一阶段开始前，按本文件执行：

- 建立 `audio-player` 组件目录
- 按本文件拆分页面组件
- 先完成状态模型设计，再接具体 UI

Phase 3 不再讨论页面结构，只处理：

- session 模型
- 队列结构
- 切歌与来源上下文
