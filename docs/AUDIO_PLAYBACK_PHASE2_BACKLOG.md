# 音频播放页二期能力清单

> 时间点：2026-03-20
>
> 背景：专业播放页首版已经完成，当前需要把“下一阶段值得做什么”固化成一份有优先级和依赖说明的 backlog，避免后续需求再次发散。

## 1. 当前基线

当前已具备：

- 专业播放页 `/audio/works/[id]`
- 全局播放器与播放页状态同步
- 队列 / 上一首 / 下一首 / 循环 / 随机
- 创作者更多作品 / 相关推荐 / 最近收听
- 轻量播放事件上报

当前仍然没有：

- 歌词
- 播放速度切换
- 继续收听跨设备同步
- 专辑 / 合集 / 播单
- 章节导航
- 用户侧“最近收听”页面

## 2. 优先级分层

### P1：短期可交付

- 播放速度切换
- 最近收听页面
- 播放页与迷你播放器的“展开 / 收起”更强联动
- 相关推荐质量提升
- 播放失败态更完整

### P2：中期增强

- 歌词 / 文本稿件
- 章节导航
- 继续收听（服务端持久化）
- 创作者音频合集页

### P3：长期能力

- 用户播单
- 收藏夹播放队列
- 跨设备播放进度同步
- 深度音频分析卡片

## 3. 候选能力详解

### 3.1 播放速度切换

价值：

- 对语音类、访谈类、讲述类内容很有帮助
- 改动范围小，用户感知明显

建议支持：

- `0.75x`
- `1.0x`
- `1.25x`
- `1.5x`
- `2.0x`

前端改动：

- `MusicPlayer` 增加 `playbackRate`
- 播放页主控制区增加速度选择器
- 底部播放器可只保留当前速度展示，不一定需要全部按钮

后端依赖：

- 无

优先级：

- `P1`

### 3.2 最近收听页面

价值：

- 当前已有本地最近收听数据，但只在播放页侧栏展示
- 单独页面可把“继续收听”从局部能力升级成稳定入口

建议路由：

- `/audio/history`

前端改动：

- 抽出最近收听列表组件
- 提供清空历史能力
- 与全局播放器 session 结合

后端依赖：

- 首版无；可先完全基于本地存储

后续增强：

- 可扩展为服务端同步

优先级：

- `P1`

### 3.3 相关推荐质量提升

当前问题：

- 相关推荐接口已经建立，但推荐逻辑仍然偏简单
- 目前是“同作者优先 + 标签补齐 + 热门兜底”

下一步建议：

- 加入协同信号：
  - 标签重合度
  - 时长相近
  - 近期热度
  - 创作者相近风格

后端依赖：

- 可先在 `AudioWorkService.ListRelatedWorks` 内增强
- 不需要额外表结构即可做第一轮改进

优先级：

- `P1`

### 3.4 播放失败态

当前问题：

- 当前更多依赖浏览器原生媒体错误表现
- 页面层没有完整的失败提示、重试提示、源地址异常提示

建议补充：

- 加载中
- 播放失败
- 链接失效
- 自动播放被阻止
- 当前曲目损坏，跳过到下一首

前端依赖：

- `MusicPlayer` 暴露 `error` 状态
- 页面根据错误类型显示不同提示

优先级：

- `P1`

### 3.5 歌词 / 文本稿件

价值：

- 对歌曲、人声作品、朗读作品都有附加价值
- 能显著提高停留时间与互动质量

建议数据模型：

- `lyrics` 文本
- 可选 `lrc` 时间轴内容

前端呈现：

- 有时间轴时做滚动高亮
- 无时间轴时作为文本稿件展示

后端依赖：

- 新增字段或附表
- 创作者编辑入口

优先级：

- `P2`

### 3.6 章节导航

适合场景：

- 讲述类音频
- 有段落结构的长音频
- 教程 / 访谈 / 播客式内容

建议能力：

- 显示章节标题
- 点击章节跳到指定时间
- 当前章节高亮

后端依赖：

- 作品 metadata 中增加章节数组

优先级：

- `P2`

### 3.7 继续收听服务端同步

价值：

- 本地最近收听只能在单设备可用
- 服务端同步后，登录用户可跨设备恢复收听

建议最小数据模型：

- `user_id`
- `audio_work_id`
- `last_position_sec`
- `updated_at`

建议接口：

- `POST /api/v1/audio/works/:id/progress`
- `GET /api/v1/users/me/audio/history`

优先级：

- `P2`

### 3.8 创作者音频合集页

价值：

- 当前只有“创作者更多作品”列表，没有结构化合集
- 适合形成更强的创作者展示面

建议方向：

- 先做“创作者音频主页”
- 后续再做“合集 / 系列”

优先级：

- `P2`

### 3.9 用户播单

价值：

- 是播放体系长期最有价值的功能之一
- 但会带来更明显的数据建模、权限、排序、分享复杂度

建议延后：

- 等最近收听、继续收听、合集页都稳定后再做

优先级：

- `P3`

## 4. 建议研发顺序

### 推荐顺序 A

1. 播放速度切换
2. 播放失败态
3. 最近收听页面
4. 相关推荐质量提升
5. 歌词 / 文本稿件
6. 章节导航
7. 服务端继续收听

### 推荐顺序 B

如果你更偏内容消费增长，而不是播放器精细打磨：

1. 最近收听页面
2. 服务端继续收听
3. 相关推荐质量提升
4. 创作者音频合集页
5. 歌词 / 文本稿件

## 5. 依赖关系

### 无后端依赖即可做

- 播放速度切换
- 最近收听页面（本地版）
- 迷你播放器展开优化
- 播放失败态增强

### 需要后端接口或数据结构支持

- 继续收听服务端同步
- 歌词
- 章节导航
- 用户播单
- 创作者合集

## 6. 当前建议

如果继续沿“短周期、高反馈”的路线推进，建议下一轮优先做：

1. 播放速度切换
2. 播放失败态
3. 最近收听独立页面

这三项都能在当前基础上快速落地，而且能明显提升真实使用体验。
