# 涂油斗地主专业化升级计划

## 1. 方向纠正

本项目的目标不是新增一款平行游戏，也不是在 `dou-dizhu` 旁边再开一个“涂油斗地主”分支。

正确方向是：

- 继续沿用现有 `apps/web/src/app/games/dou-dizhu` 这条产品线
- 用户可见名称统一升级为“涂油斗地主”
- 在现有大厅页、房间页、战报页和牌桌组件上做专业化重构
- 保留当前 WebSocket、房间、AI 演示、战报链路，不另起一套纯前端单机实现

结论：

- `dou-dizhu` 是内部 slug 和接口路径
- “涂油斗地主”是产品名称和全站展示名称
- 本次是原位升级，不是新开项目

## 2. 当前代码基础

现有核心文件：

- `apps/web/src/app/games/[slug]/play/page.tsx`
- `apps/web/src/app/games/dou-dizhu/rooms/[roomId]/page.tsx`
- `apps/web/src/app/games/dou-dizhu/matches/[matchId]/page.tsx`
- `apps/web/src/components/games/doudizhu-play-stage.tsx`
- `apps/web/src/lib/api-client.ts`
- `apps/web/src/lib/games.ts`

当前已有能力：

- 真人房和 AI 演示房入口
- WebSocket 房间连接
- 叫分、出牌、托管、结算的服务端链路
- 最近对局和战报查询
- 基础牌型预判和出牌提示

当前主要问题：

- 产品命名仍然是通用“斗地主 / 经典斗地主 / Dou Dizhu”
- `doudizhu-play-stage.tsx` 职责过大，大厅、房间、手牌、提示、结算、榜单都混在一起
- 页面风格更接近“功能接入页”，不够像专业棋牌产品
- 牌桌视觉没有形成“涂油斗地主”专属识别
- 局内反馈还不够细，很多状态仍是工程视角，不是玩家视角

## 3. 总目标

把现有 `dou-dizhu` 直接升级成一款更专业的“涂油斗地主”，重点不是改玩法品类，而是提升这四层：

- 产品层：名称、文案、入口、叙事统一
- 视觉层：形成专属牌桌、牌背、按钮和结算风格
- 交互层：叫分、选牌、出牌、等待、托管、结算反馈更完整
- 工程层：把大组件拆清楚，规则和 UI 解耦，类型严格

## 4. 命名策略

### 4.1 对用户展示

所有用户可见文案统一改为“涂油斗地主”，包括：

- 游戏标题
- 大厅文案
- 房间页标题
- 牌桌提示
- 按钮文案
- 结算弹窗
- 战报页标题

禁止继续出现：

- “经典斗地主”
- “Dou Dizhu”
- “斗地主实验页”

### 4.2 对内部实现

为了控制重构风险，内部 slug、文件名、接口类型暂时保留：

- 路由继续使用 `/games/dou-dizhu/...`
- API 类型继续使用 `Doudizhu*`
- 组件文件名可以逐步迁移，不强制一次性重命名所有内部标识

原则：

- 先统一产品展示名
- 再逐步整理内部命名
- 不为了“名字好看”打断已跑通的联机链路

## 5. 页面与组件重构方案

### 5.1 不新开游戏路由

不再新增：

- 平行单机路由
- 平行玩法分支
- 独立 HTML 原型页

本次只升级现有页面：

- `/games/dou-dizhu/play`
- `/games/dou-dizhu/rooms/[roomId]`
- `/games/dou-dizhu/matches/[matchId]`

### 5.2 组件拆分

当前 `apps/web/src/components/games/doudizhu-play-stage.tsx` 过于臃肿，建议拆成以下模块：

- `doudizhu-play-stage.tsx`
  - 作为容器层，只负责数据拉取、WebSocket、状态编排
- `doudizhu-lobby-panel.tsx`
  - 负责大厅入口、AI 开始、真人房入口
- `doudizhu-table.tsx`
  - 负责中央牌桌布局和桌面状态
- `doudizhu-seat.tsx`
  - 负责玩家座位、角色、行动态、剩余牌数
- `doudizhu-hand.tsx`
  - 负责我的手牌显示、选牌、拖拽排序
- `doudizhu-action-bar.tsx`
  - 负责提示、叫分、出牌、过牌、托管
- `doudizhu-settlement-modal.tsx`
  - 负责结算展示和再开一局
- `doudizhu-history-panel.tsx`
  - 负责最近对局入口或战绩入口的游戏化展示

### 5.3 逻辑模块拆分

从大组件中继续抽离纯函数和视图模型：

- `apps/web/src/lib/games/doudizhu/cards.ts`
  - 牌面显示、花色、点数转换
- `apps/web/src/lib/games/doudizhu/combo.ts`
  - 牌型识别、比较、文案映射
- `apps/web/src/lib/games/doudizhu/selection.ts`
  - 选牌、重选、显示顺序
- `apps/web/src/lib/games/doudizhu/presenter.ts`
  - 服务端数据到 UI 文案的映射
- `apps/web/src/lib/games/doudizhu/theme.ts`
  - 主题色、状态色、提示色

## 6. 视觉升级计划

### 6.1 品牌视觉

全局视觉统一为“涂油斗地主”：

- 标题艺术字：28px，加粗，金色 `#d4af37`，绿色描边 `#0b5e2d`
- 核心桌布：深绿色 `#085726`
- 牌面底色：米白 `#f8f5e6`
- 强调色：橙色 `#ff7a45`

### 6.2 牌桌风格

牌桌页不再像“接入状态看板”，而是像真正可玩的棋牌游戏页面：

- 主视觉中心是桌面，不是房间工具
- 减少后台感卡片堆叠
- 用桌布纹理、灯光、高光和中心出牌区建立空间感
- 按钮和提示框统一加入“涂油”风格占位

素材占位必须预留：

- `/* 涂油斗地主牌背暗纹素材位置 */`
- `/* 涂油 logo 占位 */`
- `/* 涂油按钮油渍纹理占位 */`

### 6.3 页面风格边界

严格避免在牌桌页出现明显 SaaS/后台感元素：

- 大段表单区
- 数据面板式卡片堆叠
- 运营后台式 tabs
- 管理台式榜单布局

允许保留的功能必须游戏化表达：

- 房间入口
- 最近对局
- 战报查看
- 托管状态

## 7. 交互升级重点

### 7.1 叫分阶段

保留服务端叫分机制，但前端反馈要做全：

- 玩家点击 `1 分 / 2 分 / 3 分 / 不叫` 后立即高亮当前操作
- 其他分数按钮按规则禁用
- 底部广播“XX 叫了 X 分”
- AI 叫分时显示“AI1 正在叫分...”
- 地主确定后，顶部和座位都要有“涂油地主”标识
- 底牌翻开时做明确视觉强调

### 7.2 选牌体验

当前已有基础选牌，但还不够产品化，需要补齐：

- Hover 放大和橙色阴影
- 选中上移、边框、轻微旋转
- 空选、错选、非法压牌的即时提示
- 牌型实时识别结果
- 支持前端展示顺序调整

拖拽排序的原则：

- 只影响前端展示顺序
- 不改变服务端手牌内容
- 保证与 `privateState.hand` 同步时不会丢牌

### 7.3 出牌反馈

需要补强的不是规则是否存在，而是反馈是否专业：

- 出牌成功后中央出牌区要有明确聚焦
- 炸弹和王炸要有更强提示层级
- 非自己回合时操作按钮要清晰降级
- AI 出牌时要有“正在思考”状态
- 违规信息要讲明原因，不只显示失败

### 7.4 托管体验

当前已有 `toggle_auto_play`，但展示层还不够明确：

- 座位区标识“托管中”
- 操作条显示“已托管，由系统代打”
- 托管开启和关闭都要有状态反馈
- 回合到自己时如果托管开启，要明显标记是系统代打

### 7.5 结算体验

现有结算信息已经有基础数据，但表现不够像正式产品，需要升级：

- 弹窗主标题统一为“涂油斗地主”
- 明确显示地主胜/农民胜
- 展示倍率、炸弹、春天/反春
- 分数变化更清楚
- 增加“再来一局”主按钮
- 战报入口作为次操作存在

## 8. 战报页和大厅页一起升级

### 8.1 大厅页

`/games/dou-dizhu/play` 不应再像“实验页入口”，要改成真正的游戏大厅：

- 标题统一为“涂油斗地主”
- 文案从“接入、实验、链路验证”改成玩家导向表述
- AI 演示房入口继续保留，但按钮和介绍改成游戏语言
- 真人房入口保留，但弱化表单感

### 8.2 房间页

`/games/dou-dizhu/rooms/[roomId]` 要成为沉浸式主战场：

- 顶部信息更简洁
- 中央牌桌优先级最高
- 状态、倒计时、底牌、上一手、当前轮次统一围绕桌面组织
- 旁侧信息减少看板感

### 8.3 战报页

`/games/dou-dizhu/matches/[matchId]` 需要从“技术时间线页”升级成“对局战报页”：

- 标题统一为“涂油斗地主战报”
- 把结果榜做成更像比赛结算
- 时间线保持可读，但不要有后台日志风格
- 地主、倍率、特殊事件用更强视觉分层

## 9. TypeScript 和工程规范

### 9.1 类型要求

- 保持 `apps/web/tsconfig.json` 的 `strict: true`
- 所有新增函数显式声明参数和返回类型
- 禁止 `any`
- 纯逻辑函数从组件中抽离

### 9.2 组件规范

- 容器组件负责数据和状态
- 展示组件尽量纯展示
- 文案映射不要散落在多个 JSX 片段里
- 牌型识别、文案映射、状态文案都收敛到工具层

### 9.3 风格实现

当前项目以 `tsx + Tailwind` 为主，但这次建议混合使用：

- 页面结构：Tailwind
- 牌桌复杂视觉：CSS Module
- 动效：优先 `framer-motion` 或明确的 CSS 动画

## 10. 实施阶段

### Phase 1：统一命名与页面文案

修改范围：

- `apps/web/src/lib/games.ts`
- `apps/web/src/app/games/[slug]/page.tsx`
- `apps/web/src/app/games/[slug]/play/page.tsx`
- `apps/web/src/app/games/dou-dizhu/rooms/[roomId]/page.tsx`
- `apps/web/src/app/games/dou-dizhu/matches/[matchId]/page.tsx`
- `apps/web/src/components/games/doudizhu-play-stage.tsx`

目标：

- 用户可见标题全部变成“涂油斗地主”
- 清理“经典斗地主 / 实验页 / 接入验证”这类工程化表达

验收标准：

- 页面任何主要标题都不再出现通用命名
- 产品定位统一

### Phase 2：组件拆分和逻辑抽离

目标：

- 缩小 `doudizhu-play-stage.tsx`
- 把牌型、文案、显示映射抽成工具模块
- 把大厅、牌桌、手牌、操作条、结算拆成子组件

验收标准：

- 大组件职责清晰下降
- 纯逻辑代码不再深埋 JSX
- 类型边界更清楚

### Phase 3：牌桌视觉重构

目标：

- 深绿色桌布 + 米白牌面 + 涂油橙色点缀
- 牌背暗纹和 logo 占位
- 按钮、提示框、结算弹窗统一风格

验收标准：

- 房间页和牌桌主体具备独立品牌识别
- 不再像通用后台样式拼接

### Phase 4：局内交互打磨

目标：

- 选牌反馈专业化
- AI 思考态明确
- 叫分和出牌状态更清晰
- 托管、错误、非法操作都有明确反馈

验收标准：

- 玩家能靠界面清楚理解当前局势
- 错误提示具体
- 关键回合无“状态不明”问题

### Phase 5：大厅和战报专业化

目标：

- 大厅更像游戏入口，不像测试容器
- 战报页更像对局回顾，不像原始日志

验收标准：

- 大厅、房间、战报风格统一
- 既保留现有能力，又更接近正式产品

- 重写后端接口和 WebSocket 协议
- 替换现有 `dou-dizhu` slug
- 为了命名统一一次性重命名所有 API 类型
